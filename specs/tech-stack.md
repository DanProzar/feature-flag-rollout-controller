# Tech Stack

| Concern | Choice |
|---------|--------|
| Language | **TypeScript** (strict mode) end to end |
| Web framework | **Next.js** (App Router) — UI pages + Route Handlers for the HTTP API |
| UI components | **shadcn/ui** (`base-nova` style, Base UI primitives) on **Tailwind CSS v4**, `lucide-react` icons |
| Database | **MongoDB** |
| DB access | Official `mongodb` Node.js driver, with **Zod** schemas for validation at the boundaries |
| Testing | **Vitest** (unit + integration); integration tests run against a real MongoDB container |
| Runtime / packaging | **Docker** + **Docker Compose** (`app` + `mongo` services) |
| Package manager | npm |
| Lint / format | ESLint (Next.js config) + Prettier |

## Architecture

```
src/
  domain/        # pure evaluator + types, no I/O (hashing, rule ordering)
  data/          # MongoDB config, client, indexes, repositories, reset, seed
  server/        # request schemas, HTTP helpers, app clock, services + container
  app/           # Next.js App Router: admin UI pages
  app/api/       # Route Handlers: thin wrappers over src/server services
  components/ui/ # shadcn/ui components (generated by the shadcn CLI, owned by us)
  components/    # app-specific components composed from components/ui
  lib/utils.ts   # shared UI helpers (`cn` class-name merging)
```

- **Domain is pure**: `evaluate(flag | null, { userId, cohorts }, stickyValue?) -> { enabled, reason, persist }`.
  No database or framework imports, so it's trivially unit-testable.
- **Data layer** wraps MongoDB behind small repository factories taking a `Db` (and a `Clock` where
  they write timestamps): flags, assignments, audit, users, cohorts. `client.ts` holds the only
  connection singleton (`getDb`/`closeDb`, cached on `globalThis`); `ensureIndexes(db)` is the only
  place indexes are created; every document read is parsed with a Zod schema from `schemas.ts`.

```
src/data/
  config.ts       # loadConfig(): MONGODB_URI, MONGODB_DB (Zod)
  client.ts       # getDb() / closeDb()
  indexes.ts      # ensureIndexes(db)
  schemas.ts      # Zod schemas for stored documents
  errors.ts       # isDuplicateKeyError, DuplicateCohortError
  flags.ts assignments.ts audit.ts users.ts cohorts.ts   # repositories
  reset.ts        # resetFlagsAndAssignments(db)
  seed.ts         # SEED_COHORTS, SEED_USERS, SEED_FLAGS, seed(db, clock)
  seed.cli.ts     # `npm run seed`
  index.ts        # public API
```
- **Server layer** (`src/server`) composes them. `createFlagService` orchestrates PUT (upsert +
  audit) and evaluation (load flag → load sticky only for sticky flags → evaluate → persist via
  `insertIfAbsent`, answering the value actually stored); `createResetService` clears flags and
  assignments and freezes the app clock. `getServices()` connects, runs `ensureIndexes` once per
  process (cached on `globalThis`, failures retried) and builds the services on `appClock`;
  integration tests swap in their own with `setServicesForTesting`.
- **Route handlers** (`src/app/api`) only validate the path key and body, call a service and
  respond; they never import `src/data` or the driver. All are `dynamic = "force-dynamic"`.

```
src/server/
  schemas.ts      # FlagKeySchema, PutFlagBodySchema, EvaluateBodySchema, ResetBodySchema (Zod)
  http.ts         # parseJson, parseKey, invalidKey, actorIdFrom
  clock.ts        # appClock, freezeClock, unfreezeClock (delegate on globalThis)
  config.ts       # testEndpointsEnabled(env)
  flags.ts        # createFlagService: put, evaluate, audit
  reset.ts        # createResetService: reset(now)
  container.ts    # createServices, getServices, setServicesForTesting
  index.ts        # public API
```
- **UI layer** builds the admin pages from shadcn/ui components. They are copied into
  `src/components/ui` with `npx shadcn@latest add <component>` and may be edited like our own code;
  `components.json` holds the shadcn configuration.

## Data model (MongoDB)

`flags`
```ts
{ _id, key: string /* unique */, description?: string,
  enabled: boolean /* false = kill switch on */, percentage: number /* 0–100 */,
  includeCohorts: string[], excludeCohorts: string[],
  sticky: boolean,
  createdAt: Date, updatedAt: Date }
```

`assignments` (sticky)
```ts
{ _id, flagKey: string, userId: string, value: boolean, createdAt: Date }
// unique index on { flagKey, userId }
```

`audit` (append-only)
```ts
{ _id, at: Date, key: string, actorId: string | null /* null when no X-User-Id */,
  before: Flag | null /* null when the PUT created the flag */, after: Flag }
// index on { key, at }
```

`users` (fixed UUID v7 ids for seed users; `users.create` generates them with `uuid`'s `v7()`)
```ts
{ _id, userId: string /* UUID v7, unique */, name: string, cohorts: string[] }
```

`cohorts` (reference catalogue for UIs; flags and users store cohort keys as plain strings and are
not validated against it)
```ts
{ _id, key: string /* unique */, name: string, description: string }
```

- Sticky writes use an upsert with `$setOnInsert` on the unique index so concurrent first
  evaluations can't create conflicting assignments — the first write wins and both callers return it.

## Seed data

- `npm run seed` (`tsx src/data/seed.cli.ts`, loads `.env` if present) creates indexes and seeds
  `cohorts` (4), `users` (6) and `flags` (5, one per evaluation reason). Each collection is seeded
  only when it is empty; flags get no audit entries. Reset empties `flags`, so the seed flags return
  on the next run.
- Compose runs it as a one-shot `seed` service (Dockerfile `seed` stage) after `mongo` is healthy;
  `app` starts once it has completed successfully.

## Hashing

- Bucket = `crc32(utf8(flagKey + ":" + userId)) % 100`, using the standard CRC-32 (IEEE 802.3,
  same as zlib) and treating the result as an **unsigned** 32-bit integer.
- Implementation: `zlib.crc32` from `node:zlib` (Node.js ≥ 22.2, already unsigned), over
  `Buffer.from(input, "utf8")`. Pin the Node version in the Dockerfile accordingly.
- Including `flagKey` in the input keeps buckets independent across flags.
- The algorithm is fixed: changing it would reshuffle every non-sticky user.

## HTTP API

| Method & path | Body | Response |
|---------------|------|----------|
| `PUT /api/flags/:key` | all flag fields (`enabled`, `percentage`, `includeCohorts`, `excludeCohorts`, `sticky`) | `200 { flag }` |
| `POST /api/flags/:key/evaluate` | `{ userId, cohorts? }` | `200 { enabled: boolean, reason }` |
| `GET /api/flags/:key/audit` | — | `200 { entries }`, oldest first |
| `POST /api/test/reset` | `{ now }` (required) | `200 { now }`; clears flags and sticky assignments (audit is kept) |

### Request validation
- `:key` must be a lowercase slug, `^[a-z0-9][a-z0-9._-]{0,99}$` (1–100 chars), on every
  `/api/flags/:key/*` route; otherwise `400`.
- Bodies are parsed with the Zod schemas in `src/server/schemas.ts`. Unknown fields are
  **stripped**, not rejected. `percentage` is an integer `0..100`; `userId` and cohort entries are
  trimmed and must be non-empty; cohort arrays are de-duplicated (first occurrence kept).
- Every `400` has the body `{ error, issues }`: `error` is `"Invalid JSON"` (with `issues: {}`),
  `"Invalid request body"` or `"Invalid flag key"`; `issues` maps field names to messages (Zod
  `fieldErrors`). Unexpected errors are left to Next (`500`). Unlisted methods get `405`.

### `PUT /api/flags/:key` — upsert
- `key` comes from the path; a `key` in the body is ignored.
- All five fields are **required**; a missing or invalid field returns `400`. The body fully
  replaces the stored flag (create if missing, replace if present) — no partial updates, no defaults.
- Every PUT appends one audit entry `{ at, key, actorId, before, after }`, even if nothing changed:
  `at` = server clock, `actorId` = the `X-User-Id` header, or `null` if absent,
  `before` = `null` when the flag didn't exist.
- The kill switch is a PUT with `enabled: false`; there's no separate endpoint.

### `POST /api/flags/:key/evaluate`
- `cohorts` is optional and defaults to `[]`.
- Runs the rules in `mission.md`; `reason` is one of `FLAG_NOT_FOUND`, `KILL_SWITCH`,
  `COHORT_EXCLUDED`, `COHORT_INCLUDED`, `STICKY`, `PERCENTAGE`.
- An unknown flag returns `200 { enabled: false, reason: "FLAG_NOT_FOUND" }`, so clients fail safe.

### `GET /api/flags/:key/audit`
- Returns `{ entries }` for that key, `at` as ISO-8601 strings; `{ entries: [] }` for a key with no
  history.

### `POST /api/test/reset` — test support
- Deletes all flags and sticky assignments. The **audit log is not cleared**; a flag re-created
  after a reset gets an entry with `before: null`.
- `now` (ISO-8601, **required**; missing or invalid → `400`) freezes the server clock at that
  instant until the next reset, so audit `at` values are deterministic in tests.
- Served only when `ENABLE_TEST_ENDPOINTS` is exactly `"true"` (checked per request, before the
  body is parsed); otherwise it returns `404`. `docker-compose.dev.yml` enables it;
  `docker-compose.yml` keeps it off. Seed flags are not re-inserted.

## Clock

- All timestamps (`at`, `createdAt`, `updatedAt`) come from one injectable `Clock` module
  (`now(): Date`), never `new Date()` directly, so the test reset can freeze it.
- The app uses `appClock` (`src/server/clock.ts`): the system clock until `freezeClock(at)`, then
  that instant until the next reset. Its delegate lives on `globalThis`, so it is shared by every
  route handler and survives dev hot reloads.

## UI

- Styling is Tailwind CSS v4 utility classes only (no CSS modules or CSS-in-JS). Theme tokens are the
  shadcn CSS variables in `src/app/globals.css`; change the look there, not per component.
- Prefer a shadcn/ui component over hand-rolled markup (e.g. `Table`, `Form` inputs, `Slider`,
  `Switch`, `AlertDialog`, `Badge`, `Card`, `Sonner` toasts). Add components as they are needed.
- Icons come from `lucide-react`.

## Conventions

- Validate all request bodies with Zod; return `400` with details on failure.
- Config via environment variables (`MONGODB_URI`, `MONGODB_DB`, `ENABLE_TEST_ENDPOINTS`).
- Tests live in a `tests/` folder inside the module they cover (e.g. `src/domain/tests/*.test.ts`);
  integration tests are named `*.int.test.ts`.
- Vitest has two projects: `unit` (`npm test`, no MongoDB needed) and `int` (`npm run test:int`).
  `npm run test:all` runs both; `npm run test:coverage` runs both with a 100% gate on `src/domain`,
  `src/data`, `src/server` and `src/app/api`. API integration tests call the exported route
  handlers directly (`src/app/api/tests/helpers.ts`). Integration tests need the compose `mongo` with its port exposed:
  `docker compose -f docker-compose.yml -f docker-compose.dev.yml up -d mongo`. Each test file uses
  its own `feature_flags_test_<random>` database (`useTestDb()`), dropped afterwards.
